# NX Nitro Cache

> 最新バージョン: 1.1.1（2026-10-31）。ローカルの未公開変更を反映し、ソースと配布物を揃えた同期リリースです。

NX Nitro Cacheは、NexaPressの公開ページをHTMLファイルとして保存し、ページ表示を高速化する拡張機能です。

一度生成されたページをキャッシュとして保存し、次回以降のアクセスではデータベース処理やHTML生成処理を減らします。

## 主な機能

- 公開ページのHTMLキャッシュ
- キャッシュ機能の有効化・無効化
- キャッシュ保存時間の設定
- キャッシュ対象外URLの設定
- 管理画面からの全キャッシュ削除
- キャッシュファイル数の表示
- キャッシュ使用容量の表示
- 保存容量・件数・1ページのサイズ上限
- 許可するHostの設定
- キャッシュ配信時のセキュリティヘッダー保持
- URL指定・関連ページの部分削除
- 更新・削除後の事前生成キューとCLIワーカー
- HIT率・処理時間・キャッシュ対象外理由の集計
- URLごとの保存時間（最長一致・完全一致優先）
- 投稿更新時のキャッシュ自動削除
- 固定ページ更新時のキャッシュ自動削除
- カテゴリ更新時のキャッシュ自動削除
- テーマ変更時のキャッシュ自動削除
- ログイン中の管理者はキャッシュ対象外
- 管理画面はキャッシュ対象外
- POST通信はキャッシュ対象外

## 動作環境

- NexaPress 2.2.0以上
- PHP 8.0以上
- 事前生成を使う場合はPHPのcURL拡張

## インストール

NexaPress管理画面の拡張機能ページから、ZIPファイルをアップロードしてインストールします。

```text
nx_nitro_cache-1.1.1.zip
```

インストール後、拡張機能を有効化してください。

管理画面の「キャッシュを許可するHost」に、サイトで使用するドメインを
1行につき1件入力して保存してください。例：example.com、www.example.com。
標準以外のポートを使う場合は example.com:8080 のように指定します。
未設定時はキャッシュを使用せず、通常のページ表示を行います。
HostヘッダーやSERVER_NAMEからドメインを自動登録することはありません。

### 1.1.0へ更新する場合

旧形式のキャッシュは配信しません。新しい形式で本文、必要なHTTPヘッダー、
URL、投稿・カテゴリ等の依存情報を一体で保存します。旧ファイルは閲覧・保存・
管理画面での清掃時に削除します。1.0.1の許可Host設定等は引き継ぎます。
初めて設定する場合は許可Hostを指定してください。事前生成は初期状態では無効です。

## キャッシュ保存先

キャッシュファイルは、NexaPress本体の次の場所へ保存されます。

```text
storage/cache/nx_nitro_cache/
```

拡張機能のリポジトリ内にはキャッシュファイルを保存しません。

## キャッシュされるページ

初期設定では、次の公開ページがキャッシュ対象になります。

- トップページ
- 投稿ページ
- 固定ページ
- カテゴリを含む投稿ページ
- カスタムURL形式の公開ページ

## キャッシュされないページ

次のアクセスはキャッシュされません。

- NexaPress管理画面
- ログインページ
- インストール画面
- POSTリクエスト
- ログイン中の管理者
- Cookie・Authorization等の認証情報を含むアクセス
- セッションにデータがあるアクセス
- クエリーパラメータを含むURL
- 設定で除外したURL
- エラーページ
- リダイレクトレスポンス
- Set-Cookie、Vary、private、no-store、no-cache等を返すレスポンス
- リクエストごとのnonceを含むCSP、圧縮済み本文等を返すレスポンス

NexaPress本体や他の拡張機能が返すキャッシュ禁止指示は上書きしません。
PHPのsession_start()が付けるCookieやキャッシュ禁止ヘッダーも対象です。
そのため、これらを常に返す構成ではページキャッシュを保存しません。

## 保存容量と自動削除

初期上限は合計100 MiB、1,000件、1ページ2,048 KiBです。
上限に達した場合は古いキャッシュから削除し、1ページの上限を超えたHTMLは
保存せず通常表示します。合計容量には保存したヘッダー等の情報も含みます。
通常のキャッシュ閲覧時は最大1分間隔、保存時は毎回、期限切れを清掃します。

更新成功イベントのある本体ではイベントに連動して削除します。
旧版のURLによる互換処理では、認証済みの更新について投稿・設定等の実データが
変わったことを確認してから削除します。未認証アクセスや、データが変わらない
ログイン転送・入力エラーだけでは削除しません。

## 関連ページだけを削除する

「更新時に削除する範囲」の初期値は「関連ページだけ」です。
投稿の更新時は、その投稿、トップ・記事一覧、旧・新カテゴリの一覧、
依存関係を特定できないカスタムページを削除し、無関係な記事・固定ページは残します。
投稿IDで追跡するため、URL変更前のキャッシュも削除します。
固定ページ・カテゴリの変更も対応する依存情報を使います。

テーマや共通設定の変更、更新対象を特定できないイベントでは全削除します。
全ページに最新記事ウィジェットや独自のメニューを表示するテーマでは、
「全ページ」を選択してください。これらのテーマ独自の依存先は自動検出しません。
管理画面から特定のURLを手動削除することもできます。

## URLごとの保存時間

「URLごとの保存時間」に、設置先からのパスと秒数を1行に1件指定します。

~~~text
/ 300
/post/* 3600
/page/about 86400
~~~

設定範囲は60～604800秒、最大200ルールです。末尾の*は前方一致です。
最も長く一致するパスを優先し、同じ長さなら完全一致を優先します。
指定のないURLは共通の保存時間を使います。HTTPレスポンスが指定する
max-age等が短い場合は、その短い期限を優先します。

## キャッシュの事前生成

1. 許可Hostを設定し、「更新・削除後に事前生成する」をオンにします。
2. 「事前生成するサイトURL」に設置先までのURLを指定します。
   例：https://example.com/blog
3. 主なURLを1行につき1件指定して保存します。設置先からのパスで入力します。
4. 管理画面の「事前生成を開始」で、主なURLと現在保存済みのURLを予約できます。

更新・削除が成功すると、対象だった保存済みURLや更新後の公開URLも追加します。
この管理画面を開いている間はJavaScriptが認証済みの制御APIを使い、1件ずつ処理します。
キューの上限は200件です。ネットワークエラーは間隔を空けて最大3回試行します。
停止・取消後もすでに実行中の1件は完了します。

画面を閉じた状態でも自動実行する場合は、サーバーのcron等に次のコマンドを
毎分実行するよう登録してください。コマンド内のパスは設置環境に合わせます。
自動でサーバーのスケジュール設定を書き換えることはありません。

~~~sh
php /path/to/nexapress/extensions/nx_nitro_cache/warm-cache.php --root=/path/to/nexapress --limit=10
~~~

CLIのPHPにもcURL拡張が必要です。1回の上限は10件、処理時間の目安は25秒です。
同じキューを複数ワーカーや管理画面から操作しても、1件を重複取得しないよう
一定時間の実行予約を記録します。

事前生成は許可したサイトURLだけを取得し、CookieやAuthorizationを送りません。
リダイレクト追従、任意外部URLの登録、TLS証明書検証の無効化は行いません。
内部・予約アドレスへの接続は初期状態で拒否します。開発・イントラ環境では
「内部アドレスへの接続を許可する」を明示的にオンにできます。
PHPセッション由来のものを含め、no-storeやSet-Cookie等の応答は保存しません。
保存できない理由や接続失敗は事前生成の実行状況で確認できます。

## 効果測定

HIT率はHIT÷（HIT＋MISS）です。Cookie付きアクセス等のBYPASSは分母から外します。
MISS後に保存できなかった応答は別の件数と理由で表示します。
HIT時と保存成功時の平均処理時間は、拡張機能開始からの経過時間です。
ブラウザの総表示時間やキャッシュがなかった場合との差を計測するものではありません。

事前生成や管理画面からのアクセスを含む集計です。同時アクセスでロックを取得できない
計測は省略するため、数値は概数です。IP、Cookie値、認証情報、閲覧履歴は記録しません。
管理画面から計測の停止や集計のリセットができます。

## 開発時の確認

PHP 8.0以上のphpとphp-cgi、Python 3をPATHに設定して実行します。
一時フォルダ内のデータとテスト用の本体クラスを使用し、実サイトやDBは変更しません。

~~~text
python tests/security.py
python tests/features.py
~~~

認証・Cookieの除外、実際のCGIレスポンスヘッダー、更新成功時の削除、
容量・件数上限、並行書込み、旧形式の拒否、削除前から生成中だったページの
再保存防止を確認します。テスト用ファイルは配布ZIPには含まれません。
追加機能のテストでは、ローカルHTTPサーバーへの実接続で事前生成を確認します。
このテストにもPHPのcURL拡張が必要です。

## 各ファイルの役割

### `bootstrap.php`

拡張機能のPHPファイルを読み込み、管理画面のルートとページキャッシュ処理を登録します。

### `includes/Settings.php`

キャッシュの有効状態、保存時間、除外URLなどの設定を管理します。

### `includes/SettingsController.php`

管理画面から送信された設定の保存とキャッシュ削除を処理します。

### `includes/CacheManager.php`

キャッシュファイルの保存、取得、削除、件数取得、容量計算を担当します。

### `includes/PageCache.php`

公開ページへのアクセスを判定し、キャッシュの読込みとHTML保存を行います。

### `includes/CacheCleaner.php`

投稿、固定ページ、カテゴリ、テーマなどが更新された場合にキャッシュを削除します。

### `admin/dashboard.php`

キャッシュ設定とキャッシュ状況を表示する管理画面です。

## リリースZIP

リリース用ZIPには、拡張機能フォルダを1つ含めてください。

正しい構造：

```text
nx_nitro_cache-1.1.1.zip
└─nx_nitro_cache
    │  manifest.json
    │  bootstrap.php
    │  README.md
    │  LICENSE
    │  img.png
    │
    ├─admin
    ├─assets
    └─includes
```

ZIP直下には、必ず `nx_nitro_cache` フォルダを配置します。

`manifest.json` などのファイルをZIP直下へ直接配置すると、NexaPressの拡張機能アップロードでは認識されません。
